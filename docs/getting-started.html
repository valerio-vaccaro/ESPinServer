Step-by-step tutorial

OverviewProtocolSecurity
Use test data only. ESPinServer is experimental, unaudited firmware. Use a disposable wallet, PIN, and isolated local network.

This guide takes a blank ESP32 from firmware build to a first test connection with a Blockstream Jade. The repository version is available as Markdown for offline reading.

1. Prepare the hardware

You need an ESP32 or ESP32-S3 board listed in platformio.ini, a USB data cable, a computer with the repository, a shared 2.4 GHz Wi-Fi network, and a Jade configured for custom PIN-server use.

2. Build and flash

From the repository root, build the firmware:

./venv/bin/pio run

Upload the standard ESP32 environment over USB:

./venv/bin/pio run -e esp32dev -t upload
./venv/bin/pio device monitor -b 115200

For an ESP32-S3 DevKitC-1, replace esp32dev with esp32-s3-devkitc-1. If more than one serial port is present, add --upload-port <port>. You can alternatively use the browser flasher with a packaged GitHub Actions build.

3. Configure Wi-Fi

  1. After first boot, connect to the ESPinServer-Setup Wi-Fi network.
  2. Complete the captive portal with the local Wi-Fi credentials.
  3. Return your computer or phone to the same local network as the ESP32.

If the captive portal does not open automatically, use the network notification or the address shown by the setup page. The serial monitor runs at 115200 baud and is useful for finding the assigned IP address.

4. Open the administration page

Use the mDNS name or the device IP:

https://espinserver.local/
https://<device-ip>/

The certificate is generated and self-signed by the device, so a browser warning is expected. Verify the local address, then accept the certificate for this test device. The administration page is HTTPS on port 443.

5. Create or unlock storage

On a new device, create a 12–64 character storage password containing an uppercase letter, lowercase letter, number, and printable symbol. Enter it twice. The password is not stored; it derives the keys that protect the encrypted /pins.bin database.

After a reboot, enter the password once to unlock the database. The PIN API returns 423 until storage is unlocked.

6. Check the Pairing page

Open Pairing and confirm that both API URLs use http:// and port 80. These are not the same as the browser URL:

Browser:  https://192.168.1.42/
Primary:  http://192.168.1.42:80
Fallback: http://espinserver.local:80

The page also shows the server public key and generates the QR code. Edit and save the URLs if your network needs different addresses.

7. Pair and test the Jade

  1. Open the Jade custom PIN-server configuration flow.
  2. Scan the QR code on the Pairing page.
  3. Confirm the URLs and server public key on the Jade.
  4. Lock and unlock the Jade using a test PIN.

The first successful setup calls POST /set_pin and creates a record. Later unlocks call POST /get_pin. The official Jade script can configure the same values over USB when QR scanning is unavailable.

8. Check results

Use Dashboard for request counters and slot usage. Use Diagnostics for record metadata and recent connection logs; it never displays PINs.

Wrong PIN behavior is intentionally delayed: the first failure starts a 5-second cooldown, the second starts a 60-second cooldown, and the third invalidates the record. Unknown or incorrect PINs receive a dummy response with the normal protocol shape.

Maintenance

  • Refreshing the certificate requires trusting the new certificate again.
  • Generating a new server key changes the QR public key and requires re-pairing clients.
  • Wiping the database removes all stored PIN records.

Troubleshooting

If the browser cannot connect, try the IP address instead of espinserver.local, confirm the computer is on the same LAN, and check the serial monitor. If the Jade cannot connect, verify that the QR contains HTTP port-80 URLs rather than the HTTPS browser URL. Status 423 means storage is locked; 429 or 403 indicates failed-PIN cooldown or invalidation.

For wire fields and key derivation, read the protocol notes. For threat-model limitations, read the security model.
