Getting started

OverviewProtocolSecurity
Use test data only. This firmware is a research demonstration, not a production PIN service.

Build and first boot

  1. Flash the generated image using the browser flasher or PlatformIO.
  2. Connect to the ESPinServer-Setup Wi-Fi network and configure local Wi-Fi in the captive portal.
  3. Open https://espinserver.local/ or https://<device-ip>/. Accept the warning for the device-generated self-signed certificate.
  4. Create a storage password on first boot. It must be 12–64 ASCII characters and include uppercase, lowercase, a number, and a symbol. Enter it twice.
  5. On later boots, enter the password once to unlock the encrypted PIN database.

Pair a Blockstream Jade

  1. Make sure the Jade and ESP32 are on the same local network.
  2. Open the ESPinServer Pairing page. Confirm the primary and secondary URLs use http:// and port 80; these are the PIN API URLs, not the browser URL.
  3. Use the Jade custom PIN-server configuration flow to scan the QR code. The QR contains the API URLs and ESPinServer public key.
  4. Lock and unlock the Jade with a test PIN. ESPinServer creates the record through /set_pin; subsequent unlocks use /get_pin.

If the QR workflow is unavailable, the official Jade repository includes set_jade_pinserver.py for setting the primary URL, secondary URL, and public key over USB.

HTTP and HTTPS ports

Use HTTPS for the ESPinServer pages:

https://espinserver.local/
https://<device-ip>/

Use HTTP only for the Jade-compatible API:

http://<device-ip>:80/set_pin
http://<device-ip>:80/get_pin

Old pairing URLs saved by earlier firmware versions are migrated from https://…:443 to http://…:80 when possible.

Maintenance

The Configuration page can refresh the self-signed HTTPS certificate. After refreshing, reconnect to the site and trust the new certificate again. Generating a new server key invalidates clients using the previous public key. Wiping the database removes all stored PIN records.
