Security model

OverviewGetting startedProtocol
Do not use in production. This project demonstrates a protocol on a general-purpose ESP32. It is not a secure element and has not been audited.

What is stored

  • The server private key is stored in NVS under the application namespace.
  • The PIN database is stored as a binary file at /pins.bin in LittleFS.
  • Records contain PIN verification material, a key share, replay state, and counters.

Physical attacker impact

Anyone able to read or modify the flash can extract or replace these values. The PIN itself is not stored as plaintext, but the stored verification material can provide information for offline guessing and the key share must be treated as exposed. An attacker can also replace the server key or firmware.

Safer deployment expectations

  • Use an isolated lab network.
  • Use throwaway PINs and test wallets.
  • Never reuse credentials or key material from a production device.
  • Erase the device before disposal or repurposing.
  • For production, use a reviewed implementation with secure boot, flash encryption, authenticated transport, protected key storage, and an audited threat model.

See the Blockstream Jade repository and its security policy.
