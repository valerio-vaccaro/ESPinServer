PIN-server protocol

OverviewGetting startedSecurity

ESPinServer is the ESP-based PinServer. This implementation follows the Blockstream/Jade PIN-server v2 blind-oracle shape for local interoperability testing.

Endpoints

EndpointMethodPurpose
/set_pinPOSTRegister a wallet PIN record
/get_pinPOSTVerify a PIN record
/configGET/POSTConfigure the server

Request envelope

JSON requests contain a base64-encoded binary envelope:

client public key       33 bytes, compressed secp256k1
replay counter          4 bytes, little-endian
encrypted payload       remaining bytes

The decrypted payload contains a 32-byte pin_secret, optional client entropy, and a 65-byte recoverable signature. Clients normally derive pin_secret = SHA256(PIN).

Cryptography

ECDH-derived keys are separated with blind_oracle_request and blind_oracle_response. Payloads use AES-256-CBC with PKCS#7 padding and HMAC-SHA256 authentication.

Server behavior

  • Records are identified by a hash of the recovered client public key.
  • Replay counters must increase.
  • Failed attempts trigger progressive cooldowns.
  • Unknown or incorrect PINs receive dummy responses.
  • After three failed attempts, a record is invalidated.

For complete wire-level notes, read PINSERVER_PROTOCOL.md. Reference: Blockstream pinserver.
